# Прокси Xray для Plasma 5

Виджет панели Plasma 5 для системной службы Xray. Одна служба держит два независимых прокси-туннеля, основной и дополнительный. У каждого туннеля свой профиль, свой переключатель и кнопка «Пинг». Профили берутся из своей папки, из подписок и из ссылок `vless://`. Поддерживаются VLESS (REALITY, WebSocket/TLS, XHTTP/TLS) и WireGuard. Системный прокси виджет не меняет: приложения подключаются к портам туннелей сами.

Проект сделан для Plasma 5.27 и проверен на одной машине. Доступность конкретного сервера нужно проверять отдельно — для этого и есть «Пинг».

## Возможности

- Два туннеля в одной службе Xray. Порты по умолчанию:

  | Туннель | SOCKS5 | HTTP |
  |---|---|---|
  | Основной | `127.0.0.1:10808` | `127.0.0.1:10809` |
  | Дополнительный | `127.0.0.1:10818` | `127.0.0.1:10819` |

- У каждого туннеля своя вкладка. Выключенный туннель закрывает свои порты, но помнит профиль: при включении вернётся он же. Выбор профиля включает туннель.
- «Пинг» запрашивает `https://www.google.com/generate_204` через HTTP-порт туннеля. Он показывает время ответа, а также адрес и страну выхода по `https://www.cloudflare.com/cdn-cgi/trace`. После выбора профиля или включения туннеля проверка запускается сама. Пинг не требует пароля.
- Адреса портов и IP выхода копируются щелчком.
- Профили собраны в группы и ищутся по названию и исходному имени. Одинаковые серверы из разных групп показываются один раз.

## Что нужно

- Plasma 5.27, Python 3.11 или новее, `curl`, `pkexec` (polkit), systemd.
- Xray, запущенный системной службой, например установленный [официальным скриптом](https://github.com/XTLS/Xray-install): `/usr/local/bin/xray`, `/usr/local/etc/xray/config.json`, `xray.service`.
- Конфиг Xray в раскладке, которую понимает виджет (см. ниже).

### Конфиг Xray

Виджет меняет только свою часть конфига, а остальное проверяет и не трогает. Основной туннель должен уже быть в конфиге:

- входы `socks` и `http` на `127.0.0.1` с портами основного туннеля, других входов нет;
- исходящее соединение `proxy-primary` — VLESS или WireGuard без балансировщиков и observatory;
- последнее правило маршрутизации — `{"type": "field", "network": "tcp,udp", "outboundTag": "proxy-primary"}`.

Готовый образец — [`xray-config.example.json`](xray-config.example.json): замените в нём сервер на свой. Дополнительный туннель виджет добавит сам при первом выборе профиля для него. Его входы, исходящее соединение `proxy-secondary` и правило маршрутизации ставятся перед общим правилом основного туннеля.

## Установка

```sh
git clone git@github.com:aadegtyarev/xray-plasma-widget.git
cd xray-plasma-widget
./install.sh
```

Скрипт ставит:

- пакет виджета;
- помощник `~/.local/libexec/xray-widget-system` с модулями;
- команду `~/.local/bin/xray-widget`;
- папку профилей `~/.config/xray-widget/profiles` и начальный `~/.config/xray-widget/config.toml`.

Для системной части он один раз вызывает `sudo`: ставит помощник `/usr/local/libexec/xray-widget-profile-admin` (`root:root`, `0755`) и создаёт `/etc/xray-widget/system.toml` из образца.

Существующие настройки скрипт не перезаписывает. Прежний `~/.local/bin/xray-widget` сохраняет рядом с датой в имени. В конце он показывает, видит ли помощник службу.

После первой установки:

1. Проверьте `/etc/xray-widget/system.toml`: службу, путь к конфигу Xray и к самому Xray.
2. Положите профили в `~/.config/xray-widget/profiles` или добавьте подписку в `config.toml`.
3. Добавьте на панель виджет «Прокси Xray».

Обновление: `git pull && ./install.sh`, затем `systemctl --user restart plasma-plasmashell.service`, чтобы панель подхватила новый виджет.

### Системные настройки

`/etc/xray-widget/system.toml` описывает службу, которой управляет виджет. Образец — [`system.example.toml`](system.example.toml). Файл читает помощник с правами root, поэтому он должен принадлежать root и быть закрыт на запись для остальных.

| Ключ | Что задаёт |
|---|---|
| `service` | служба systemd с Xray |
| `config` | конфиг Xray этой службы |
| `xray` | исполняемый файл Xray: им конфиг проверяется перед перезапуском |
| `route_mark` | необязательная метка `sockopt.mark` для соединений туннелей, например чтобы трафик Xray обходил системный VPN по `ip rule`. Если она задана, помощник требует её в профиле основного туннеля и копирует в профиль каждого туннеля |
| `ports.primary`, `ports.secondary` | порты SOCKS5 и HTTP туннелей на `127.0.0.1` |

## Профили

Откуда брать профили, задаёт `~/.config/xray-widget/config.toml`; образец с пояснениями — [`config.example.toml`](config.example.toml). Файл может содержать токены подписок, поэтому держите его с правами `0600`.

Профили собираются из групп `[[group]]`. Группы идут в списке в порядке файла, внутри группы профили сортируются по названию без учёта флагов. У группы есть имя и один источник:

- `folder` — папка с профилями. Каждый файл `*.json` — исходящее соединение (outbound) Xray, имя файла — название профиля, например `🇩🇪 Мой сервер (REALITY).json`. Поле `tag` можно не указывать: помощник сам называет соединение по туннелю. Папка и файлы должны быть доступны только вам (`0700` и `0600`);
- `subscription` — ссылка `https://` на подписку со ссылками `vless://` с REALITY или WebSocket/TLS. Список кешируется в `~/.local/share/xray-widget/subscriptions/` (права `0600`) и обновляется раз в 12 часов; после неудачи повтор не чаще раза в час. Обновить сразу: `xray-widget refresh`;
- `links` — ссылки `vless://` прямо в `config.toml`.

Раздел `[labels]` задаёт понятные подписи профилям подписок и ссылок: `"исходное имя" = "подпись"`. Исходные имена видны в развёрнутой строке профиля, по ним работает поиск.

Профиль из папки или ссылки узнаётся по настройкам: одинаковый сервер из двух групп показывается один раз со всеми исходными именами, а переименование файла не сбрасывает выбор. Профиль подписки узнаётся по группе и имени. Причина: поставщики подписок при каждой выгрузке меняют SNI и shortId, а на общих входных адресах именно они выбирают локацию.

WireGuard работает внутри Xray на userspace-стеке (`noKernelTun`), без системного интерфейса и маршрутов; AmneziaWG не поддерживается. Профили, которые виджет не умеет запускать, показываются в группе «Недоступны» с причиной.

### Перенос из Throne или Nekoray

```sh
./import-throne ~/.config/Throne/config/profiles
```

Скрипт переводит профили в файлы Xray в `~/.config/xray-widget/profiles`. Он понимает старый и новый формат Throne: VLESS REALITY, WebSocket/TLS, XHTTP с сохранённым конфигом Xray и WireGuard. Существующие файлы скрипт не перезаписывает, уже имеющиеся профили пропускает и ключей на экран не выводит. После переноса файлы можно переименовать как удобно.

## Команды

Всё, что делает виджет, доступно и из терминала:

| Команда | Что делает |
|---|---|
| `xray-widget status` | состояние службы, туннелей и список профилей в JSON |
| `xray-widget ping primary` | пинг основного туннеля; для дополнительного — `secondary` |
| `xray-widget refresh` | обновить подписки сейчас |
| `xray-widget select <id>` | выбрать профиль основного туннеля; `select-secondary` — дополнительного |
| `xray-widget select original` | вернуть основному туннелю профиль из конфига до первого переключения |
| `xray-widget enable secondary off` | выключить туннель; `on` — включить |
| `xray-widget restart` | перезапустить службу Xray |

## Как устроены права

Виджет и `xray-widget-system` работают от вашего имени. Менять конфиг Xray может только корневой помощник `/usr/local/libexec/xray-widget-profile-admin`. Его запускает `pkexec` после подтверждения администратора. Профиль передаётся ему через стандартный ввод, не в командной строке.

Помощник:

1. Читает `system.toml` и принимает только известную раскладку конфига и проверенные профили VLESS и WireGuard.
2. Перед первым изменением сохраняет исходный конфиг рядом с ним как `widget-baseline.json`.
3. Меняет профиль или порты одного туннеля, проверяет конфиг командой `xray run -test` и перезапускает службу.
4. Проверяет HTTPS через `example.com` на порту включённого туннеля. При ошибке он пытается вернуть прежний конфиг.

Системные маршруты и настройки DNS помощник не меняет. Если выбранный профиль невозможно подтвердить, например после перезапуска службы не из виджета, виджет показывает «Профиль не определён».

## Простой режим: пользовательская служба

Без системной службы и прав администратора виджет может переключать готовые конфиги Xray, запущенного пользовательской службой. Туннель тогда один, а профили — целые конфиги Xray.

Нужны Plasma 5, Python 3, Xray и пользовательский systemd. Схема такая:

- исполняемый файл Xray: `~/.local/share/xray-proxy/xray`;
- активная конфигурация: `~/.local/share/xray-proxy/primary.json`;
- готовые конфигурации: `~/.local/share/xray-proxy/profiles/*.json`;
- служба: `xray-proxy.service` запускает Xray с активной конфигурацией.

Каждая конфигурация для переключения должна содержать ровно один HTTP-вход на `127.0.0.1:20172`. Настройка исходящих соединений и, если нужны, файлов GeoIP/GeoSite остаётся за пользователем. Для SOCKS5 нужен отдельный SOCKS-сервер или реле: виджет их не создаёт.

**Не копируйте в репозиторий конфигурации с ключами и паролями.** Используйте только доверенные конфигурации: Xray запускает их от вашего имени. Каталог с конфигурациями должен быть доступен только владельцу (`0700`), файлы — только владельцу (`0600`).

1. Создайте указанную структуру в домашнем каталоге, поместите туда исполняемый файл Xray и подготовленный конфиг. Сохраните конфиг как `primary.json` и как файл в `profiles/`. Не перезаписывайте свои существующие конфигурации.
2. Создайте `~/.config/systemd/user/xray-proxy.service`, указав существующий исполняемый файл и активный конфиг:

   ```ini
   [Unit]
   Description=Xray explicit HTTP proxy
   Wants=network-online.target
   After=network-online.target

   [Service]
   Type=simple
   ExecStart=%h/.local/share/xray-proxy/xray run -config %h/.local/share/xray-proxy/primary.json
   Restart=on-failure
   RestartSec=5
   UMask=0077

   [Install]
   WantedBy=default.target
   ```

3. Проверьте конфиг командой `~/.local/share/xray-proxy/xray run -test -config ~/.local/share/xray-proxy/primary.json`. Затем выполните `systemctl --user daemon-reload` и `systemctl --user enable --now xray-proxy.service`. Запуск без входа пользователя требует отдельно настроенного lingering в systemd.
4. Из каталога проекта установите помощник и пакет виджета:

   ```sh
   install -d -m 700 ~/.local/bin
   install -m 700 xray-widget ~/.local/bin/xray-widget
   kpackagetool5 --type Plasma/Applet --install package
   ```

5. Добавьте на панель виджет «Прокси Xray».

Имя файла профиля без `.json` показывается в списке. Допустимы латинские буквы, цифры, `_` и `-`, не более 80 символов. При выборе помощник проверяет конфигурацию через Xray и перезапускает службу. При ошибке запуска он пытается восстановить предыдущую конфигурацию.

Индикатор показывает состояние процесса, а не доступность интернета. Если служба не запускается, проверьте `journalctl --user -u xray-proxy.service`. Журнал может содержать сетевые данные; проверьте его перед отправкой.

```sh
python3 -m unittest discover -v
```
